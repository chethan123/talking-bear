Rig: SVG DOM debug view and canvas stress

One slider per pose channel (plan §4.6.6). The same pose is drawn twice, side by side: as SVG DOM built from the generated parts and bone matrices (plan §4.6.1, dev only), and by the app's Canvas 2D renderer. The max pixel difference between the two is sampled once a second; it is informational. The SVG view draws the parts only: the mouth and the dizzy stars are parametric canvas geometry, so Jaw, MouthW, MouthRound, Teeth and Stars show on the canvas alone. A second difference compares the parts only (the renderer with those five channels at 0), so a real mismatch between the rig and the SVG view still shows.

Stress (X-A1, plan §5): every spring gets a random impulse every 200 ms, the idle layers run on top of the sliders' pose, and the canvas renders every frame at the app stage's size (the viewport) with the chosen DPR. Lab pages have no CSS sizing, so on a high-DPR screen the stress canvas shows larger than the viewport; the cost is in its backing store, which matches the app's. The SVG view and the pixel difference pause meanwhile, and the page scrolls to the canvas while stress runs: read the statistics in the log, or scroll up. A viewport change (rotation, the toolbar collapsing) resizes the stress canvas and restarts the statistics. Use remote DevTools for the full trace (docs/lab.md).
